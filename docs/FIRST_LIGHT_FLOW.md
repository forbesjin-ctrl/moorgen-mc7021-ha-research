# 首灯流程：从本机采样到HA真实状态验收

v0.10.0新增统一的“首灯流程”，打开应用默认进入这一页。原有演示、采样、分析、报告、首组核对和HA接入六页保留，新页把它们串成同一组普通灯的下一步。**本版仍在本地构建与发布准备中；已发布v0.9.0不含这一入口或内置驱动打包。** 下载状态以[发布页](https://github.com/forbesjin-ctrl/moorgen-mc7021-ha-research/releases)为准，不把本文当作新版已经可下载的通知。

工具现在有一个固定、有限的明文实验实现：符合两轮原件和本机凭据检查时，可以生成单灯HA安装包，业主不写Python、不上传报文。它不是通用协议推导器；认证、加密或字段不匹配时停止在具体缺口。真实住户样本、已验证厂家驱动和真实HA单灯验收仍均为0。生成安装包只表示满足本机实验打包条件，不表示已成功登录主机或已控制实灯。

## 先准备什么

- 业主在自己住宅，认准MC7021和同一组看得清实际亮灭的普通开关灯，原App和原面板本来可正常控制。
- Mac、iPhone、USB数据线以及已有Apple `rvictl`组件；已确认的主机当前IP和自己的iPhone UDID。不猜IP、不扫描，不自动安装系统组件。
- 一个本机私有数据目录。完整报文、事件、报告、复核、配方、驱动和HA诊断都留在业主环境，不要求交给项目人员。
- 到HA安装时才需要HA备份、图形文件管理、复制组件、重启和添加集成的基础能力，见[自助前检查](SELF_SERVICE.md)。

不必先提供账号密码。只有真实首组通过、独立两轮原件及固定线格式全部匹配后，工具才询问本户当前合法且已知的摩根账户输入。只有云端账号、不了解本地凭据或不愿输入时，保持待支持，不猜密码、不复制抓包认证值或旧token。

## 1. 读“当前下一步”，现场采首轮

打开“首灯流程”，选择本机数据目录后点“检查并继续”。没有原件时显示现场采样任务；“执行所选下一步”可转到采样页，准备本身不启动抓包或网络。本人填写已知IP、iPhone UDID及灯名，确认现场仍是同一组，再手动开始。

每轮完整做十步正常操作，分别记录实际灯和App显示：

1. 先开始采样，再正常打开App目标页，记录连接和初始同步。
2. App开灯第一次。
3. App关灯第一次。
4. App开灯第二次。
5. App关灯第二次。
6. App留在页面，只用原面板开灯，观察App独立反馈。
7. 只用原面板关灯，观察反馈。
8. 正常关闭App，不注销账户。
9. App关闭期间用同一面板开灯，App显示记录不可见。
10. 正常重进目标页，实物不再变化，记录当前读回。

等待停止、保存和接口清理完成。初始亮灭的准备与恢复只用已知的这组灯操作；不切家庭网络、不改路由/厂家配置，不操作其他灯、场景、总断电或安防。失败或不确定如实保留，不能编辑原件让结果通过。

已有完整样本可点“选择首轮原件…”，选择含`session.json`、`events.jsonl`、`traffic.pcap`的文件夹。外来样本先用Finder完整复制到所选私有数据目录；用于实验打包的真实样本须位于该目录`captures/`的直属采样文件夹，且具有实际采样时的真实来源声明，不修改来源标记绕过检查。来源未知的资料仍可离线研究。

## 2. 选完整对象，保存首组人工核对

从“首灯流程完整对象”下拉选择原件中实际出现的完整八字节标识，再点“重新读取原件”。不自动选首个候选，不用房间名、配置偏移或别户标识当地址；改变对象后不能沿用旧结论。

按当前任务进入“首组核对”，逐项判断样本质量、同灯身份、重复开关、面板独立反馈、重进App读回，写明帧号和现场依据。ACK、执行应答、按钮变色或缓存不是真实状态。不确定保留待验证/需补采，不为继续而盲勾。

通过记录只是业主人工声明，绑定这一轮原件、主机和完整对象，不认证住宅或实物身份。返回首灯流程重新检查，旧报告、保存的流程JSON或下游安装材料都不能替代重新读取原件。

## 3. 加入独立第二轮

再正常采同一主机、同一组灯的一轮，完整十步，另存新目录，不覆盖旧原件。点“加入独立第二轮…”选择完整新轮。PCAP内容必须不同；复制、改名或只改事件文件不算独立样本，真实和合成也不能混用。

工具重新检查两轮的大小/SHA256、普通灯标签、完整对象、丢包、TCP连接边界、连接与认证顺序、开关和状态字节、新连接查询及读回。缺动作证据时可按[补采向导](SAMPLING_GAPS.md)补同一组；软件策略不支持时进入[会话工作台](SESSION_WORKBENCH.md)看具体原因，不无限重复相同采样。

## 4. 匹配固定实验实现，再做本机凭据核对

在首灯流程选择匹配驱动任务，点“执行所选下一步”。这一步调用随工具提供的固定匹配器，不执行导入插件，也不让业主编写Python。当前只支持一个窄分支：

- 唯一的实际TCP主机端口、完整新连接和明确明文协商；不猜填9000。
- 空连接请求、连接应答恰好`160=00`；账户认证恰好用户名/密码字段12、13及空成功类应答。
- 同一组普通灯的重复开关、面板状态、关闭App期间改变后新连接读回；序号匹配逐次加一并回绕。
- 每次新连接有同一对象的`48`单设备查询及相关`04`独立详情应答；ACK与执行应答不作状态。
- 不支持加密、RSA、动态密钥、token/session认证、AppID或未知状态字段等分支，发现即拒绝打包或继续运行，不忽略未知字段。

只有**同一轮真实首组核对通过，且两轮线格式匹配**，才显示本户用户名及密码输入。密码框隐藏文字；输入的是正常使用的当前合法用户名和原密码，不是从抓包复制的字符串，也不是Mac管理员密码。

点“仅本机核对并继续”。用户名按原样ASCII核对，密码的固定检查只在内存比较原样ASCII、MD5十六进制小写/大写三种已有线编码，必须唯一匹配两轮全部认证帧；支持范围为1–128个非全空白的可打印ASCII字符，用户名不得带首尾空白。它不尝试网络登录、不猜密码，不改变原账户或认证方式。不匹配、匹配不唯一、输入范围不支持或取消时，保持待支持。

Mac不把用户名、密码、凭据摘要或原认证字节写入生成的工件、命令参数、环境变量或日志。保存的是编码类型、来源绑定与本机检查结论，仍不是实际认证成功证明。原始PCAP可能已经包含认证信息，继续作为私有原件保管。

匹配通过后，工具自动新建本机HA向导，加入固定实验驱动和绑定清单，生成私有HA安装包。代码来自应用随附的固定实现，不从旧报文重放登录或序号。Mac不加载驱动、不连接设备；`online_ready`仍为`false`，住宅兼容性和物理状态未验证。

## 5. 在HA安装，重新输入当前凭据并明确授权

首灯流程可点“单灯HA向导”继续[五步操作](HA_WIZARD.md)。先备份HA，用已有图形文件工具将安装包的`custom_components/mc7021_single_light`复制到HA配置目录。已有同名目录时停止核对，不盲目覆盖。Mac不代登录、安装或修改HA。

在HA界面重启、添加“MC7021 单灯业主验收”。核对捕获的固定主机、端口、单灯完整对象及驱动版本/哈希。使用内置实验驱动时，**在HA重新输入本户当前合法用户名和原密码**；HA将其保存到业主自己的集成配置。Mac安装包没有这些输入，HA配置及其备份按私有资料保管。

确认可信来源与版本说明，另行明确授权这一组普通灯的现场在线读写，HA才加载驱动，连接绑定的已知IP/实际端口。它不发现或扫描设备，不改厂家参数，不处理其他灯。此阶段开始家庭网络通信；离线打包或点击流程概览不授权连接。

每次连接都建立新会话、使用新序号并重新认证，先对同一灯独立查询读回，再允许普通开关控制；不恢复旧token、旧认证帧或断线缓存。未知协商、认证、状态布局或读回失败时停止并保留不可用/未验证，不能尝试未知协议。首次安装成功不是验收通过。

## 6. 完成八项实灯验收

HA设备页每步先选验收步骤并开始记录，再操作；Mac填写实际亮灭、HA显示、事件ID、结论与依据，默认未知：

1. HA开灯第一次。
2. HA关灯第一次。
3. HA开灯第二次。
4. HA关灯第二次。
5. 只用原面板开灯，HA独立同步。
6. 只用原面板关灯，HA独立同步。
7. 仅断开本适配会话，HA显示不可用；断开期间用原面板改变同一组灯。
8. 重连后用新接收代次独立读回，HA与此刻实物一致，不用断线前缓存。

下载当前集成的私有诊断，导回Mac核对。请求成功、ACK、命令完成、乐观更新或旧会话回调不作真实状态。缺步骤、来源/哈希冲突或观察不一致时保持待验证/需重测；先解决这一组，不扩大其他设备。全部条件成立后，流程才引导其他普通灯逐组独立核对；通过仍是业主对这一组灯的现场声明，软件不能看见灯本体。

## 保存、接续与当前边界

资料保存在所选数据目录，均为私有材料：

- `captures/`：原始三文件，每轮独立保存。
- `private_first_light_flows/flow_<UUID>/`：`flow.json`和中文全过程说明，只用于显示当前状态。
- `private_driver_profiles/profile_<UUID>/`：驱动匹配及编码检查结果，不含凭据值或其摘要。
- `baseline_reviews/`及`private_ha_wizards/`：首组人工声明、驱动/安装包、HA进度、诊断与八步观察。

每次继续重读来源、核对SHA256和主机/灯路；改原件、目标、驱动或包后不能沿用旧通过。旧流程JSON不是授权令牌。没有上传、云端模型或集中收样功能；需要协助时由业主自行决定最少共享范围，不发群或公开Issue/GitHub。

后续接续先看本页、[HA向导](HA_WIZARD.md)及以下实现：`tools/first_light_flow.py`负责状态与下一步，`tools/driver_profile.py`固定匹配两轮原件和本机编码，`tools/single_light_driver.py`是随包的有限实验实现。真实首组样本仍由业主在自己环境采集；匹配不等于实机通过，未知分支应补明确的软件实现与测试，不能泛化到全屋或任意加密协议。当前真实样本、已验证厂家驱动、实灯HA验收仍均为0；合成测试只能验证代码约束。
