# 协议候选：尚待住户通信验证

本页区分程序实现证据、公开第三方实现与住户实测。这里的帧内偏移是明文帧的位置，不是配置文件偏移、寄存器或房间地址。

## 原厂App静态证据

已离线读取公开下载链取得的`com.moorgen.smarthome` 6.9.6 / code915，APK SHA-256为`c1a4862f0dec806f97cf051ced037eb75086bbfa007a896866abbfe2ea29c034`，主要协议实现位于classes5.dex。这里只公开研究摘要，不再分发安装包或反汇编。来源入口：[摩根官网](https://www.moorgen.com/)、[应用宝条目](https://sj.qq.com/appdetail/com.moorgen.smarthome)。下载对象和版本可能更新，复核时先核对实际文件哈希。

所检查SDK的明文分支由`ProtocolBean`与`LocalMsgExecute.doMessage`构造：

```text
0       0x23
1..2    L: u16LE，整帧长度 = L + 3
3..11   ASCII dooyashcp
12      协议编号
13      协议类型
14      link code
15..16  序号 u16LE
17..18  N: 数据区长度 u16LE，N = L - 17
19..    type:u16LE + value长度:u16LE + value，重复至数据区结束
末尾     0x23；整帧长度 = N + 20
```

普通灯`LIGHT_COMM`数值类型1，在已检查的带设备类型SDK调用链中选择文本`light-on`或`light-off`，经ISO-8859-1成为TLV9；通用执行构造还包含TLV16操作类别与TLV4设备标识，外层执行为4/9。枚举另有cmdNo 1/2，部分其它设备类型可走数字编码，不能仅凭枚举数字选择线上命令。

独立状态路径与执行响应分开：执行响应4/10、执行ACK4/11，数据更新5/12。设备状态更新类别TLV27=3；TLV4标识对象，TLV11首字节写入状态。普通灯开关判定是`(raw_status & 1) == 1`，其余位保留未知；不能写成“任意非零即开”或只接受精确值1。设备详情响应3/8、TLV15=4也有状态解析入口。

离线codec只有在调用者明确给出已确认普通灯的完整标识，且报文上下文正确时才解释开关；缺状态保持未知。它不把任意字段4对应的设备都当灯，也不把收到状态字节当成物理灯具已发光。

## 会话与适用限制

同一个App存在认证和加密分支。连接响应协议名给出初始状态，TLV160可能覆盖加密类型/开关，TLV93参与会话密钥处理；请求名dooyashcp不决定后续一直明文。SDK还存在用户名密码及手机号session/token认证路径。“no need”日志对应SDK匹配检查，不能当作本地免认证。

当前codec不支持加密、认证协商或网络传输。完整设备标识必须来自该户正常设备列表/通信，与设备类型和实际灯关联；不从配置键、偏移或别户标识补齐地址。SDK存在某型号字符串不证明该户固件选中了这条路径。

## 第三方公开交叉来源

[mythsman/ha-moorgen-home固定提交](https://github.com/mythsman/ha-moorgen-home/tree/675de6b5f1582642bc05b99701c17e0e9d4dd7a0)公开了明文帧与灯光HEX样本，可用于独立比较；原始PCAP未提供，未声明MC7021兼容清单。本项目不复制这些住宅样本，公共测试均为自行生成的合成帧。

该提交的普通灯状态判断为`==1`，与本次原厂最低位规则在高位也置位时不同；0/1示例不能区分二者。其客户端没有实现认证，也不能据此推定任何住户主机无需认证。第三方实测报告和本项目住户实测始终分开。

## 仍需实际回答

某户是否使用此协议分支；认证/加密条件；普通灯完整标识与类型；App重复开关的请求、应答和独立状态；面板动作后的主动推送或刷新回读；重连是否读取当前状态；状态源和缓存行为。每种主机/固件/App组合单独记录，目前不能给出全系兼容结论。
