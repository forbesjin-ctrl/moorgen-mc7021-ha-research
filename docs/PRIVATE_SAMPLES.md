# 私下提交单灯样本

先确认你愿意参与，并且自己家使用 MC7021、原厂 App 和实体面板本来就能正常控制这组灯。只采一组普通灯，不扫描设备，不改主机、面板或路由器配置。

本项目没有样本接收后端，也没有自动上传。原始文件先保留在你的电脑，不要直接上传 Issue、PR、公开仓库或业主群。

v0.2.0生成的完整`报告.html`和`report.json`也含私有端点、设备标识及原字段，同样私下处理。另有固定字段的`匿名摘要.json`只含数量与质量级别，没有原始端点/标识；本人审阅后才手动分享。工具不会代你上传任何一种报告。

## 先私聊确认，再传文件

1. 与愿意分析的项目参与者私聊，双方确认传递方式、用途和原始样本保存期限；也确认到期由谁删除副本。没有约定前不用发送原始抓包。
2. 使用不含姓名、房号或设备标识的样本编号，例如 `SAMPLE-001`。记录 MC7021 型号、固件版本、App 平台与版本；版本未知就写“未知”。
3. 附上同一组灯的事件记录：时间、App 或面板操作、实际灯亮灭、App 显示，以及是否自动更新。灯用“测试灯 A”这样的代号即可。
4. 双方同意后，通过约定的私下渠道传递原始 PCAP 和事件记录。接收者确认编号及文件是否完整，再开始离线分析。

不用另发账号密码、完整 iPhone UDID、房号、家庭地址或全屋配置。采样工具为建立 USB 记录接口而需要的 UDID 只在本机填写，不应进入共享的事件说明或公开日志。

## 原始抓包可能含什么

原始 PCAP 可能含会话、认证数据、主机或设备标识、网络地址及其他敏感字段。即使没有明文密码，也应按私密资料处理。私下接收不等于获准再转发；需要增加分析人员或延长保存时间时，先征得样本提供者同意。

如果你不愿传原始包，可以先只提供不含标识的现象描述和事件记录；这类信息能帮助定位问题，但通常不足以验证协议字段。

## 哪些结果可以公开

公开前由提供者与分析者核对，只保留支持结论所需的最少信息，例如匿名样本编号、版本组合、操作顺序、帧类型、相对时间、字段长度及解析结论。替换或省略网络地址、设备标识及可关联到住户的信息；完整时间没有必要时使用相对时间。

不要把任意改写后的认证数据或报文当作原始采样证据。替换标识、删除字段、改写加密或认证内容，可能破坏长度、校验及解析关系：

- 能仅公开解析摘要时，优先提供摘要和对应证据说明。
- 必须提供字节示例时，说明脱敏位置和处理方式，重新核对结构；无法同时保密并保留有效结构时，不公开该报文。
- 由协议结构重新构造的测试帧，明确标记“合成样本”，不得冒充真实抓包或声称其认证有效。

任何一户的成功结果都应单独记录。其他住户需要核对自己的版本组合、设备标识、协议分支和状态反馈，不能直接套用控制字节。
