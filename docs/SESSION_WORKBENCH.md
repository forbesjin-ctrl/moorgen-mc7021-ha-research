# 本机会话工作台：继续研究认证、序号和重连

v0.9.0 的会话工作台把“待软件支持”继续拆成可检查的本机证据、策略候选、反例和剩余实现缺口。业主按图形提示选择自己的原件和第二轮样本，不需要上传资料或编写 Python。**识别出认证字段或观察到序号变化，不等于认证实现已经可用；离线匹配不等于 HA 已接通。** 当前真实住户样本、已验证摩根驱动及真实 HA 单灯验收均为 0。

## 按图形提示继续

入口为“分析”→“本机会话策略工作台…”、“HA接入”第二步→“继续分析认证、会话、序号与重连…”，或缺口窗口中的“继续分析会话策略”。不需要首组先通过即可离线研究。首次可在“演示”点“演示会话策略工作台”，合成两轮只验证软件流程。

1. **选择本机原件。** 选择完整采样文件夹，保留 `session.json`、`events.jsonl`、`traffic.pcap`。工作台读取原件重新分析并绑定大小与 SHA256，不沿用旧报告作为事实。先锁定本户、同一主机、同一组普通灯和报文中实际出现的完整八字节对象。
2. **分析本轮会话。** 查看连接起止、可解析帧、方向、认证请求及结果、协商字段和序号。报文中出现了什么属于观察事实；如何用于未来连接属于策略候选。连接开始未被捕获、未知或不透明载荷、丢包和解析失败都要显示，不能解释为免认证。
3. **加入第二轮独立样本。** 用同一主机、同一组灯的另一轮正常操作对照。重复选择同一 PCAP 或复制后改名不算第二轮。对照保留不一致和反例，不只展示匹配项。
4. **查看候选与反例。** 分别检查认证字段组合、协商加密线索、发包序号变化、响应回显候选和正常重进 App 后的会话。少量吻合只支持继续验证；未知字段、矛盾样本或缺少新连接证据不能自动变成已支持策略。
5. **回到补采向导。** 证据不足时按[缺口与补采向导](SAMPLING_GAPS.md)正常补采同一组灯，例如在正常重新进入 App 前开始记录、等待同步、App 开关、面板操作和再进入 App 回读。补采准备只填写提示和目标，不自动开始抓包或连接主机。不注销账户、不改密码、不故意触发认证失败、不切断家庭网络，也不操作其他设备。
6. **满足接入条件后才进入 HA。** 只有软件内已有完整会话策略，且与本户证据匹配、具备该策略需要的合法新凭据，并通过新连接的独立状态读回，才可继续[单灯 HA 向导](HA_WIZARD.md)。没有这些条件时停在具体缺口，不能用勾选代替实现。

分析与对照在本机离线进行，不发设备请求，不扫描，不运行导入的 Python，不修改厂家或 HA 配置。完整抓包和私有分析报告可能包含认证或会话信息，保持在业主本机，不发群、Issue 或公开仓库。会话摘要应使用帧号、方向、字段类型和长度说明证据，不把认证值或密钥复制进适配配方。

## 原厂静态代码已说明什么

以下是公开 Android App 一个 SDK 路径的静态事实，不是任一住户 MC7021 的实测协议规范。研究样本为 `com.moorgen.smarthome` 6.9.6、versionCode 915：

- APK SHA256：`c1a4862f0dec806f97cf051ced037eb75086bbfa007a896866abbfe2ea29c034`
- `classes5.dex` SHA256：`530adda4f59122169a776cd819f581bf6f32f31af963b95dab87382ba469b20a`

已保存的公开来源链由[摩根官网](https://www.moorgen.com/)的 App 二维码指向[公开下载入口](http://cloud.dooya.com:9010/)，原厂手册二维码另指向[摩根下载入口](http://cloud.moorgen.com:9010/)；两条保存的下载链落到相同 APK 对象。这说明研究样本来源，不表示当前下载入口永久提供同一版本，也不证明本户固件兼容。

**连接与账户认证分开。** 原厂连接请求是 `1/1`，响应 `1/3` 后另选账户认证。请求可能附带 App ID 字段 531 和 RSA 公钥字段 530。账户认证请求为 `2/4`；`2/6` 是成功分支，`2/5` 是失败，`2/19` 是无登录权限。代码中的“不需要匹配验证”涉及 SDK/App 与主机匹配，不能当成账户认证绕过。

**登录方式不止一种。** 静态代码包含用户名/密码字段 12/13、手机或邮箱加 session 的分支、手机或邮箱加 token 和校验码的分支。能识别字段组合不代表拿到了适用于新会话的合法凭据。工具不能从旧 PCAP 猜出密码、永久复制 App session，或把旧认证帧作为新驱动的登录步骤。

**协议名不能单独证明明文。** 连接响应字段 160 可改变加密选择，字段 93 涉及随机密钥处理，某些分支还依赖该客户端的 RSA 私钥。原厂代码存在不同 AES 处理范围和填充方式。被动抓到密文不保证能恢复动态密钥；本轮工作台不承诺解密任意会话或自动生成未知加密分支。

**序号来自动态计数。** 原厂 SDK 用受类锁保护的全局计数：小于 65535 则加一，达到上限则归零；构帧时以十六位小端写入。另一路构建协议对象也会使用同一计数，因此可见 TCP 帧跳号未必就是丢包。没有在已检查的计数方法中看到“每次 TCP 重连归零”规则。工作台可统计变化并与该候选比较，未来驱动应生成自己的新序号，不能固定复制旧样本序号。

**重连走新登录并清队列。** 原厂 `reCreateSocketAndLoginServer` 先停止连接再登录；停止路径清理活动状态、连接和收发队列。应研究新会话及新状态读回，不能断线后直接重送旧开关命令或恢复旧缓存状态。实际超时、退避和会话过期规则仍需本户完整样本及对应软件实现验证。

**单设备查询和响应值不同。** 原厂单设备信息请求为 `3/7`，TLV15 的值是 `72`，即十六进制 `48`，并附带 TLV4 的完整八字节对象。设备详情响应是 `3/8`、TLV15 值 `4`，即十六进制 `04`。不能把响应值 `04` 当作单灯查询值；静态请求路径仍需本户报文确认后才谈在线使用。

## 为什么不能直接套用公开 HA 实现

已保存的[第三方公开实现固定提交](https://github.com/mythsman/ha-moorgen-home/tree/675de6b5f1582642bc05b99701c17e0e9d4dd7a0)包含一些不同选择：请求固定序号 `0`、设备查询使用全屋 TLV15 值 `1`、心跳回应回显原帧只改 link code。原厂心跳响应构造方法则生成 `6/14` 帧并使用新的全局序号。该公开客户端也未实现前述原厂账户认证流程。

这些差异是需要用本户样本比较的候选与反例。第三方作者环境可用，不等于 MC7021 本户已经验证，也不能据此关闭认证、改未知参数或默认把所有策略混用。它的重连冷却值属于该客户端实现选择，不能直接当成主机协议要求。

## 从候选到首组 HA 验收

本轮会话工作台负责离线分析和策略证据，不因为出现成功认证响应、两轮吻合、配方重建一致或完成补采就生成在线驱动。认证值、动态密钥和新凭据的合法来源、算法实现及生命周期都需要各自满足；对于未知分支，应明确显示“待新增软件实现”及已取得的线索。继续采同样的开关操作不能自动补出 RSA 私钥或证明 token 的续期方式。

可用接入路径是：已实现且匹配的完整策略 → 业主按本机提示提供必要的新凭据 → 新连接与独立单灯读回 → 可信驱动按原 HA 向导安装和启用 → 八项现场验收。新驱动生成必须使用新会话、新序号和已确认的目标绑定；旧 PCAP 只作对照证据。

八项验收仍为：HA 开/关各两次、原面板开/关、断开此适配会话后 HA 不可用、重连后用新代次独立读回对准实物。断开只针对本适配会话，不动家庭网络和原主机。ACK、执行完成、命令回显、乐观更新和断线前缓存都不算真实状态；实物亮灭和完整对象身份仍需业主现场核对。通过结论仅限这一组普通灯，不自动扩展到其他灯、调光、窗帘、场景或安防。
