# 单灯HA图形接入与验收向导

v0.10.0新增默认打开的[首灯流程](FIRST_LIGHT_FLOW.md)，把同组采样、人工核对、独立两轮、固定实验实现匹配与下述五步HA向导串起来。旧v0.9.0不包含首灯入口或内置实验驱动打包。五步仍为锁定首组、准备驱动、生成并安装HA集成、现场验收、查看结论，各步保存在本机，可载入后重新检查来源。Mac不扫描、不连接或控制家庭设备，不执行驱动源码，也不替你登录或修改HA。

当前真实住户样本与已验证摩根驱动均为0。默认在业主自己控制的电脑和HA环境自助处理，原始资料不必经过我们。没有现成驱动时，也可用图形工作台完成本地报文重算、私有编解码配方和离线验证，不要求业主编写Python。原有JSON配方及会话工作台本身不输出可执行驱动；新增首灯流程可在严格匹配当前固定窄明文分支后生成实验安装包，不能自动完成未知登录协议或实灯控制。固定实现尚无住户实测通过记录。只有完整匹配的软件、原件和必要的合法当前凭据齐备，并由业主具备[基础能力](SELF_SERVICE.md)且明确启用后，才继续现场检验是否能接通。遇到超出工具支持的协议分支，可由业主自行选择可信技术协助；只有业主主动选择并约定外部分析时，项目分析者（Codex）才接收必要资料并承担驱动实现、审阅和测试。先完成这一组普通灯的HA开关、独立状态和现场验收，再扩展。原始配置偏移不是通信地址；9000和Mo-Bus线索不等于标准Modbus。缺少证据时保持待验证，不能靠勾选生成未知控制指令。

## 推荐入口：先按首灯流程匹配固定实现

在“首灯流程”点“检查并继续”，从原件重算当前下一步。读取首轮完整三文件，人工选择报文中实际出现的完整对象，在首组页逐项核对并保存同轮真实通过记录；再加入不同PCAP的独立第二轮。两轮须同一主机、普通灯标签和完整对象，真实与合成不可混用，复制改名不能当新轮。

随附匹配器只支持空初始化、唯一明确明文协商、账户字段12/13、递增新序号、同灯48查询/04独立读回及有限普通灯状态布局。两轮线格式和同轮真实首组通过均满足后，才在本机安全输入框询问本户当前合法用户名/原密码。用户名按原样ASCII核对，密码只在内存唯一比较原样ASCII、MD5小写/大写，必须匹配全部会话；不登录、不猜密码、不保存输入值、摘要或原认证字节。只有云端账号、未知凭据、输入不支持或不愿输入时保留待支持。

成功后自动新建HA向导、加入固定实验驱动及绑定、生成私有安装包，不用业主编写Python、填写协议推断或手工导入驱动。`online_ready=false`，本机检查和打包不是当前网络认证成功或实物验收通过。加密、RSA、动态密钥、AppID、token/session及未知状态等分支拒绝；不复制旧token、认证帧或抓包序号。详见[首灯全过程及支持边界](FIRST_LIGHT_FLOW.md)。

## 固定策略未匹配：继续本机研究

点“没有匹配驱动：本机分析…”，选择包含`session.json/events.jsonl/traffic.pcap`的本地完整采样目录。不必先有通过的首组记录，也不必为了研究把未知项勾为通过。程序从PCAP及事件重算会话、对象候选和认证缺口；从下拉列表选择实际出现的完整对象后，点“生成编解码配方并离线核对”。还可点“选择第二轮样本作离线对照…”，用不同PCAP检查同一组灯的另一轮证据。无样本时可选“演示本机适配”。

结果是本机私有JSON配方及固定codec的离线比较，不是`driver.py`或HA安装包。认证/加密、请求、重连或新会话序号策略未知时，`online_ready`保持`false`，图形界面会列出定向补采需求。第二轮匹配也不等于现场控制通过。该JSON配方不能自行变成驱动。新版首灯流程只有匹配随附有限实现后才可打包；超出范围仍需明确的软件实现与测试，可在业主自己的环境处理，不要求上传或写Python。继续离线研究详见[本机适配工作台](LOCAL_ADAPTATION.md)。

## 1. 首组和灯路

在“首组核对”载入已通过的真实复核记录，再点“进入HA接入阶段→新建单灯接入向导”。第一步点“自助前检查”确认基础能力和停止条件；这只是知识自检，不检测网络或设备，不验证驱动，也不授权连接。核对主机、房间/灯名、完整八字节对象候选。向导绑定首组记录和四份来源的SHA256；来源、驱动或包发生变化后，旧安装声明和验收不能沿用。自检不替代这些检查。

不在现场可点“演示HA向导”。演示允许浏览各步、导出未实现的接口模板、保存待验证观察，不会生成可用安装包或通过真实验收。

## 2. 使用固定实验实现，或导入已有可信驱动

首灯流程已匹配并生成安装包时，直接进入下一步，不必再导入随附代码或填写四项协议依据；它已自动建立来源、完整对象、实际端口、固定代码哈希及首组绑定。来源、驱动或包变化后重新核对，旧本机凭据检查结论不证明未来认证可用。

以下为兼容的已有完整驱动导入路线，不是普通业主使用内置实现的必经步骤。

默认在业主自有环境完成采样、分析和核对，不要求回传完整目录。需要外部协助时，先自愿分享匿名现象/最少摘要，确需原件再约定用途和范围，完整目录整理见回传说明。技术核对不要求业主先判定通过，待验证记录也可供其自己选择的分析者核对。不要为了通过而勾选不懂的协议结论；业主只确认自己现场看到和做过的事实。详见[样本回传说明](PRIVATE_SAMPLES.md)。

若需要扩展未支持分支或另行实现驱动，业主自行选择的技术协助者负责重组会话、核对认证与开关语义、识别同一完整对象的独立状态、编写驱动、离线测试，以及填写协议、会话、命令、独立状态四项证据。材料不足时先补这一组，不直接重放旧报文。核对成立后，交付`driver.py`、已填完整的`driver_manifest.json`、测试与证据说明，以及单灯安装材料；均按本户实际首组及版本绑定。

业主在“HA接入”第二步点“导入可信驱动材料…”，依次选择收到的JSON清单与Python文件即可。**选择文件不等于写代码；无需打开或编辑Python，不需要填写四项协议字段或计算SHA256。** 完整清单负责自动校验来源和哈希，不匹配时可继续本机工作台分析，或由业主自选可信协助处理，不手动改IP、标识或校验值绕过。无匹配驱动时，在线安装停在准备阶段，但可继续使用本机工作台离线研究。

勾选“显示协议开发者工具（普通业主无需）”才展开接口模板及手工四证据入口。这条高级路线需要分析会话/认证、识别命令与独立状态、编写驱动和测试的能力，不是普通业主必经步骤。Mac不执行导入代码；驱动启用后以自定义集成的Python权限在HA运行。分析者提供实现、审阅和测试依据，业主阅读来源、用途和测试说明并决定是否信任此版本，不要求业主审查Python实现；静态检查仍不能证明代码安全、协议或实物身份。开发合同见`ha_component_templates/README.md`。

## 3. 生成、安装和配置HA

点“生成单灯HA安装包”。缺少有效首组、完整驱动或清单时明确拒绝，原件不会修改。安装包仅含固定桥接模板、当前驱动及绑定信息，属于私有材料，不发群或公开仓库。

用已有HA文件管理工具完整解压并复制`custom_components/mc7021_single_light`到HA配置目录。先备份HA；已有同名目录时停止并核对版本，不盲目覆盖。文件管理条件不具备时停在此步，Mac不会安装附加组件或更改服务器配置。

在HA界面重启，然后进入“设置→设备与服务→添加集成”，搜索“MC7021 单灯业主验收”。输入/核对绑定的已知主机和灯名，从安装包绑定说明核对实际捕获端口和完整对象；端口不是要猜填的配置项。使用内置实验实现时，HA配置页还要求重新输入本户当前合法用户名和原密码；HA将其保存到业主自己的集成配置，Mac安装包不含这些输入，HA配置和备份仍须作为私有资料保管。阅读固定实现或技术提供者给出的用途和测试说明，确认“我确认此驱动来源并信任此版本（已阅读用途和测试说明）”，并另行明确授权只启用本组普通灯，才会在HA载入驱动并连接该已知主机。普通业主无需审查Python源码；无法理解说明或不信任来源时停在启用前，由自己选择可信技术协助，不盲勾。业主不因本次分工授权未知设备连接。不自动发现、不扫描、不填未知端口、不写厂家配置。只有在HA明确启用后才连接这一绑定IP/实际端口和单灯对象；Mac的离线流程不等于在线授权。内置实现每次建立新会话、使用自身新序号并重新认证，先单灯独立查询读回，状态才可用，随后才允许普通开/关。未知协商、认证、状态或读回错误时停止并保持未验证，不重放旧认证或恢复断线缓存。

把实际`light.`实体ID、HA版本及配置结果填回Mac并记录。该按钮只是人工安装声明，不能替代后面的状态验收。

## 4. 八项现场验收

HA设备页包含一盏灯、验收步骤选择器、记录标记按钮以及当前驱动的断开/重连按钮。标记不会控制灯；断开按钮只断开本适配会话，不切家庭网络、不关闭原主机。每一步先选相应步骤并点“开始记录所选验收步骤”，再按说明操作同一组普通灯：

1. `ha_on_1`：HA开灯，观察实际亮和HA开。
2. `ha_off_1`：HA关灯，观察实际灭和HA关。
3. `ha_on_2`：再次HA开灯，核对新请求及独立状态。
4. `ha_off_2`：再次HA关灯，核对新请求及独立状态。
5. `panel_on`：仅原面板开灯，HA应独立更新为开。
6. `panel_off`：仅原面板关灯，HA应独立更新为关。
7. `disconnect`：断开此适配会话，确认HA不可用；按提示用面板改变灯态并记录实际亮灭，不动网络或配置。
8. `reconnect`：重连当前适配，等新代次独立读回，HA显示应与此刻实物一致，不能恢复断线前缓存。

每项在Mac填写实际亮灭、HA显示、结论、说明及对应诊断状态事件ID，点“保存本步观察并核对”。默认都是未知，不预选期望结果。需要重测时如实选需重测。ACK、命令完成、乐观更新和旧回调不能作状态。

在HA“设置→设备与服务”中找到此集成，从菜单下载诊断JSON，然后在Mac点“导入HA诊断JSON并核对…”。下载位置随HA版本可能不同，可参考[官方诊断说明](https://www.home-assistant.io/docs/configuration/troubleshooting/#download-diagnostics)。Mac显示只读事件证据，供选择事件ID；不要求HA令牌或网页登录。诊断必须匹配当前包、驱动、首组、主机及对象，重复ID、截断、缺步骤、旧日志和代次冲突会阻止通过。

## 5. 看报告再扩展

“已确认”表示程序能核对的来源与日志一致性；“待验证”是尚缺人工观察、驱动或事件的项目；“需重测”是冲突、失效或失败。正式通过须同时满足八步事件条件和每步人工观察/说明，结论仅是该业主对这一组灯的现场验收声明。驱动自行报告的独立来源仍需结合协议和实物核对，软件不证明物理身份，不认证驱动作者。

报告与进度在`private_ha_wizards/`内，权限为目录0700、文件0600。完整诊断、驱动、主机信息和安装包均只私下处理；不上传群、Issue或公开GitHub。没有自动上传。尚未完成验收时继续这一组；通过后也不把结论套用给调光、窗帘、场景或安防。
