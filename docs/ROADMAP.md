# 阶段目标

## 已有：可共同工作的研究基础

v0.4.0增加每轮私有灯名/房间标签、首组人工复核声明、多轮合成演示和本机多轮汇总。同一主机IP与UDID可在本次打开应用期间复用，每轮独立保存。首组真实采样状态为`completed`并生成报告后，声明才可选，程序不自动勾选、不把报告成功当成状态验证。换目标前需人工声明，换IP/UDID或数据文件夹重置首组阶段；清理未知阻止下一轮。

本机汇总只读所选数据文件夹`captures/`的直属采样目录，逐轮保留质量、候选和失败。相同标识只提示冲突，不归并设备、不自动生成HA设置。多轮合成演示故意让两个别名使用同一标识，展示这一边界；它不能解锁或证明首组复核。多轮功能可以提前开发，现场顺序仍是先首组对准，再扩展同类普通灯。

v0.3.0新增原生Mac应用、内置双架构Python、JSON交互worker和限定用途采样监督器。演示/分析/报告无需终端，采样使用系统授权及按钮向导。GUI和离线分析可做合成验证；管理员授权与USB采样仍未现场验证，不据此宣称兼容。

v0.2.0已有统一菜单、采样后自动离线分析、PCAP封装读取、TCP重组、事件窗口/设备/状态候选、私有中文HTML报告、固定匿名汇总、HA待验证清单，以及纯离线状态内核。完整合成演示不需要现场或手机。住户真实通信样本仍为0，尚无HA运行验证；当前不提供在线控制客户端。真实USB及管理员授权、Intel和macOS12真机仍未实测，应用尚未Apple公证。

## 下一阶段：一组普通灯证据闭环

先由一位自愿业主在自己的正常系统记录同一组普通灯的App开关、面板开关和重进App。离线逐包核对重复开关中的完整对象标识、面板变化后的独立状态与肉眼亮灭、App重进的当前状态回读。ACK、执行应答、按钮变色和报告生成成功均不算通过。证据不足先补采同一组，不扩大到其它灯。

首组人工核对一致后，再独立采其它同类普通灯，利用多轮报告检验标识映射和状态解释；出现冲突保留未知，不自动归并。另一位同型号业主的复现也应保持独立来源及版本，不能把标识直接跨住宅共用。具体要求见[多组普通灯采样](MULTI_DEVICE.md)。

## 再下一阶段：单灯HA原型

在对应参与者另行安排的实机验证中，只实现这一组灯。原主机/面板继续工作；HA状态来源必须是独立报告/已核对回读，面板改变后同步，重连读当前状态，断线标为不可用。命令发出或ACK本身不乐观改为已成功。

## 稳定后才考虑扩展

先处理认证、会话过期、丢包、缓存、重连和版本差异，再将已逐轮核对的其它普通灯纳入HA。多组采样不等于批量接管。调光、色温、窗帘、场景、全屋控制、门锁/暖通和安防不属于本次普通灯向导；不同类型需要独立证据和目标，不能直接复用普通灯字段。
