# Moorgen MC7021 × Home Assistant

业主共同研究保留 **MC7021 主机和原面板** 的 Home Assistant 接入方式。首个目标只有一组普通灯：能明确开/关，并在原面板操作或重连后取得独立状态。

**本地自助优先：业主资料不必经过本项目人员。** 原始抓包、完整报告、复核、适配配方和HA诊断默认留在业主自己的电脑及HA环境，不要求回传，不集中收样。Mac工具无自动上传。普通业主不需要写Python：v0.10.0以“首灯流程”串起采样、人工复核、独立两轮、固定实验驱动匹配、HA安装和八项实物验收。只有已实现的窄明文分支及本机凭据检查全部匹配，才生成私有单灯安装包；其他情况保留补采或软件缺口，也可继续原有离线工作台。工具不承诺自动实现未知登录协议。需要求助时先自愿分享匿名版本/现象和最少摘要，原始文件仅作为另行同意的协助选项。

**[v0.10.0 Mac图形预览版](https://github.com/forbesjin-ctrl/moorgen-mc7021-ha-research/releases/tag/v0.10.0)** 新增默认打开的第七页[首灯流程](docs/FIRST_LIGHT_FLOW.md)，每次从原始三文件、首组复核及两轮证据重算“当前下一步”。同一真实首组通过且两轮线格式匹配后，安全输入框才询问本户当前合法用户名/原密码，用户名按原样ASCII核对，密码只在内存唯一核对原样ASCII或MD5小写/大写编码；值及其摘要不进入Mac工件。匹配后用随附的固定有限实验实现自动创建HA向导、驱动绑定和安装包，不重放旧token、认证帧或序号。HA需重新输入当前凭据、由业主明确批准后才连接捕获的已知IP/端口和单灯完整对象；凭据保存在业主自己的HA。加密、RSA、token/session、AppID和未知状态分支不支持时停止，打包不是实机通过；当前真实样本、已验证厂家驱动和HA实灯验收仍均为0。

v0.9.0增加[本机会话策略工作台](docs/SESSION_WORKBENCH.md)。在缺口窗口点“继续分析会话策略”，或从“分析”选择本机原件；工具重算双向连接与认证时序、字段形状及跨连接变化、全局递增/恒定/响应回显等窄序号候选，并用不同连接或独立第二轮检验反例。正常重进App需新连接、新详情请求和独立状态候选，不能用旧缓存或ACK代替。资料只留本机，不写Python；结果是不可执行候选，不会生成未知认证、加密策略或联网驱动。动态密钥与合法新凭据不能靠被动报文保证获得，实际HA仍需匹配实现及现场验收。

v0.8.0增加[缺口与补采向导](docs/SAMPLING_GAPS.md)。采样结束清理后或重新分析本机原件时，工具自动整理结构化缺口，再按任务说明为何缺、证据在哪里、怎样正常补采和预期看到什么；需要人工核对或软件尚未支持的策略单独列出。准备补采只填同组采样表单并清空现场确认，不启动采样或网络，也不解锁其他灯或HA。更多同类报文不能保证解决未知认证或加密。

此前v0.7.0的[本机适配工作台](docs/LOCAL_ADAPTATION.md)提供无现成驱动路线：不要求首组已通过即可离线研究，从PCAP重算会话、候选和认证缺口，选择完整对象，生成私有JSON编解码配方，再用不同PCAP作第二轮离线对照。它不输出可执行驱动，`online_ready`保持`false`；离线codec一致不代表驱动完成。已有五步HA图形向导和“自助前检查”保留，具备电脑和HA基础的业主，有经过验证且匹配的完整驱动时才可能自助接通，详见[五项基础能力与三个停止条件](docs/SELF_SERVICE.md)。当前真实住户样本、已验证摩根驱动和真实HA单灯验收均为0；Intel/macOS12真机、完整HA部署和真实灯控未验证。

这是业主自发项目，非厂家项目。代码和文档公开，住户原始抓包默认不提交；业主主动选择求助时才另行约定最小分享。

## 业主怎样参加

本版下载：[v0.10.0 Mac图形预览版](https://github.com/forbesjin-ctrl/moorgen-mc7021-ha-research/releases/tag/v0.10.0)，下载`MC7021-Mac-v0.10.0-universal2.zip`，完整解压后双击`MC7021 单灯研究工具.app`。历史[v0.7.0预览版](https://github.com/forbesjin-ctrl/moorgen-mc7021-ha-research/releases/tag/v0.7.0)保留本机适配工作台，不含结构化补采向导。已发布的[v0.6.2预览版](https://github.com/forbesjin-ctrl/moorgen-mc7021-ha-research/releases/tag/v0.6.2)作为历史版本保留，不含本机适配工作台。

v0.9.0不含新版首灯流程或固定实验驱动打包。v0.10.0首次选择本机数据文件夹，默认打开“首灯流程”点“检查并继续”；原有演示、采样、分析、报告、首组核对、HA接入六页保留，共七页。每轮仍只操作同一组普通灯。不用安装Python，不用打开终端；真实采样仍需已有Apple USB抓包组件rvictl，缺少时不自动安装。报告直接用原生窗口展示，不启动网页服务器。[图形版使用说明](docs/MAC_GUI.md)包含现场要求和首次打开说明。

采样时填写本轮灯名和可选房间别名，标签只用于私下区分，不是设备地址。同一主机IP与iPhone UDID可在本次打开应用期间复用。首组采完自动检查样本质量、对象候选、重复开关、面板状态与重进App回读，再到“首组核对”逐项选择结论、填写依据及所核对的完整对象候选。可由具备分析能力的业主自行核对，或交给协助分析者；不要求等待指定人员。待验证、需补采、失败和演示不会解锁其他灯，旧版单一核对勾选框不再作为通过条件。复核记录只存本机并绑定本轮原件SHA256；重开应用可以恢复，但每次扩展前还要重新核对原件是否变化、当前主机是否匹配及清理情况。完整流程见[首组报文核对](docs/FIRST_LIGHT_REVIEW.md)和[逐组采样](docs/MULTI_DEVICE.md)。

没有匹配驱动时，在“HA接入”点“没有匹配驱动：本机分析…”，选择本地完整采样目录；也可点“演示本机适配”。从下拉列表选报文中实际出现的完整对象，点“生成编解码配方并离线核对”，再用“选择第二轮样本作离线对照…”检查另一份PCAP。无需首组先通过，也不要求改代码或上传资料。自动结果只证明可重算的编解码与事件证据，未知认证、加密、请求、重连和序号策略继续列为缺口；不能从一段抓包自动产生可长期使用的在线驱动。完整步骤见[本机适配工作台](docs/LOCAL_ADAPTATION.md)。

v0.8.0中，在“分析”点“查看缺口与补采向导”，或进入“HA接入”第二步的“缺口与补采向导”。先选任务查看依据，必要时点“重新检查原件与缺口”。只有真实原件和所选对象重新校验一致、任务确属可补采项目时，“准备同组补采（不启动）”才会填入来源主机、灯名和房间；UDID仍由本人填写或沿用当前输入，现场确认须重新勾选，再由本人点击开始。首组未通过仍只补这一组。所有补采沿用固定的正常App与面板流程，任务仅提示重点，不发送构造命令、不改路由或厂家配置。结束后重新检查缺口，不自动勾选任务完成。

资料是否充分按三类判断：**证据缺口可采、人工事实需核对、软件策略未支持**。发现明文命令或保存了完整原件，只表示已有研究材料，不等于已有可用驱动；没有认证字段也不能当作免认证。即使两轮编解码一致，仍须完整会话策略、独立状态与断线重连实现，以及HA现场验收。原件、计划、配方和报告全留在业主本机，不调用云端模型、不自动上传。

v0.10.0优先按[首灯流程](docs/FIRST_LIGHT_FLOW.md)匹配随附的固定实验实现；它只支持已核对的明文账户分支、单灯查询和独立状态，符合两轮与凭据门槛后自动创建向导及安装包，业主不用准备Python或手写清单。Mac不联网，后续安装、HA当前凭据输入、明确授权和八项现场验收仍须逐步完成。原件、驱动、主机或灯路改变后不能沿用旧结论。

兼容的手工导入路线继续保留：已有可信且匹配的完整驱动时，复核并点“进入HA接入阶段→新建单灯接入向导”，先做知识自检，再按五步继续。驱动可由业主自行选择的可信分析者在其自有环境根据真实报文实现，分析者负责四项协议证据、源码哈希和绑定清单；业主不写Python、不填协议推断。收到材料后点“导入可信驱动材料…”，依次选择完整清单JSON和driver.py，仅选择文件，不编辑源码。“显示协议开发者工具（普通业主无需）”中的四项协议字段及模板供开发者使用。Mac只做语法/接口和绑定检查，不执行代码。通过后生成单灯HA安装包；业主通过已有文件管理工具复制到HA，在HA界面确认驱动来源并信任此版本，另行明确授权只启用这一组普通灯。驱动具有自定义集成的执行权限，技术提供者应附实现、测试、来源和用途说明；普通业主不要求自行审查Python实现。静态检查不是代码安全或协议认证，知识自检也不验证网络、驱动或授权连接。

HA内提供一盏灯、验收步骤选择、标记及此适配的断开/重连按钮。Mac逐项记录HA开/关各两次、面板开/关、断线不可用、重连当前读回八项观察，导入同包诊断后自动核对事件、来源和人工物理观察。请求/ACK不作状态，旧代次回调不恢复可用；来源、驱动、包或日志变化时重新核对。缺步骤保持待验证或需重测，演示永不正式通过。详见[单灯HA图形向导](docs/HA_WIZARD.md)。原私有研究包导出保留作可选资料。

“演示 → 多轮合成演示与汇总”无需手机，故意让两个不同灯名使用同一合成标识，演示跨轮冲突提示；不能当作两组真实设备或HA配置。“分析 → 汇总本机多轮采样”只读取所选数据文件夹的`captures/`直属采样目录，逐轮生成报告并保留失败和未知，不递归搜索、不自动合并相同标识。每轮都应结束、保存并确认清理，再开始下一轮。

应用目前只有ad-hoc本地签名，未做Developer ID签名或Apple公证，其他Mac首次打开可能需要系统的单应用确认；不要关闭系统保护。真实USB与系统管理员授权路径尚未现场验证，演示/分析与离线测试不能代替实测。

## 采集后能得到什么

报告放在本机`private_reports/analysis_…/`，中文`报告.html`可用浏览器直接打开，包含：

- PCAP大小/哈希、截断/丢包、步骤覆盖和时间对齐检查；不支持或未读成功的包数显示未知。
- 首组核对的“已确认、待验证、需补采”和五项人工必需核对清单；“已确认”限定文件和记录结构事实，协议解释及真实灯路不能由程序自动确认。另存私有`首组核对.json`。
- 按操作窗口列出开关请求、执行应答、ACK、状态和用户观察；窗口关联不自动声称因果。
- TCP分段/乱序重组、重传去重、缺口和冲突提示；UDP按数据报独立解析，不扫描字节猜帧。
- 反复App开关中的完整设备标识候选，以及面板操作和重进App窗口的状态记录；默认不按设备名猜普通灯类型。
- 会话/认证、实际灯路、独立状态和HA原型仍缺什么；`HA接入待验证.json`明确留空线上参数，不能直接加载为HA配置。

同时生成固定字段的`匿名摘要.json`，只含合成/真实来源声明、数量和质量级别；没有IP、设备标识、时间、路径或原始报文。它仍需本人审阅再手动分享。**完整HTML、report.json及原始样本都保持私下处理，不上传公开仓库。** 详见[采集后的完整流程与边界](docs/AFTER_CAPTURE.md)。

多轮汇总另存`private_reports/collection_…/`，包含`collection.html`、`collection.json`和各轮独立报告，均为私有资料。房间和灯名也是操作者声明；相同8字节标识只提示字节冲突，不跨轮归并为同一设备，不计算未经验证的全屋实体总数，不生成可导入HA的猜测参数。

## 程序员可以做什么

- 核对明文帧、TLV、设备类型和状态语义，补充合成测试；从真实样本得出的结论注明匿名来源和版本组合。
- 分别验证认证/加密、目标完整标识、初次同步、面板变化、刷新回读与重连。
- 在证据足够后实现一个普通灯HA原型，状态来自已确认的设备报告；断线或未知时不可假定已成功。
- 复用`tools/light_state_model.py`的纯离线状态内核：ACK不改亮灭，重连等待新会话独立报告，超时变为不可用。该模块没有网络、HA依赖或真实控制能力。

Mac图形流程没有网络控制或重放接口；随包的固定实验实现只用于业主在HA明确启用的阶段。HA桥接模板只有在安装者确认可信驱动来源和版本、另行明确启用本组测试后，才可调用驱动连接绑定主机及控制这一组灯；项目附带的窄明文实验实现尚无住户实机通过记录，不是已验证摩根驱动或全系兼容承诺。`tools/offline_shcp.py`只解析本地应用层HEX，也可在内存生成合成候选帧；它不是PCAP解析器，生成的字节不会发送。配置偏移和内部引用不能当通信地址，Mo-Bus或9000端口不能直接等同标准Modbus。

## 离线运行

工具仅依赖Python标准库。真实采样支持Mac；离线解析和测试可在有Python3.9+的Mac/Linux运行。

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
python3 tools/check_public_tree.py
```

不接手机的完整合成演示：

```sh
python3 tools/research_tool.py --demo
```

分析已有采样文件夹：

```sh
python3 tools/research_tool.py --session-dir '/path/to/local/session'
```

旧的纯提示演练仍可用（不生成PCAP）：

```sh
python3 tools/capture_mc7021_light.py --demo
```

演练结果放在`demo_runs/`，完整合成演示会生成**合成**PCAP，旧纯提示演练不生成PCAP。报告另存`private_reports/`。这些目录被Git忽略，公开清单检查还会拒绝跟踪原始抓包、日志和未知文件。不要为分享报告而强行加入Git。
